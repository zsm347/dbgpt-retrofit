# 长期记忆：从检索到回答的证据包（候选草案）

> 状态：待评估，不是最终 schema 或实现承诺。  
> 目的：明确搜索结果应向回答模型提供哪些判断依据；避免先设计复杂的查询意图分类和状态机。
> 框架边界：Mem0 部分以 OSS `2.2.1` 为审查样本，LangMem 和 Graphiti 以项目源码审查文档中的固定提交/版本为准；这是实现对照，不代表这些框架天然共享同一种问答策略。

2026-10-08：本文件保留证据用途和覆盖边界的讨论；首版具体字段、搜索调用及回答指引已集中到 [v1 设计与实施说明](agent_long_term_memory_v1_design.md)的实施说明 8、10、11。本文的桌面问题分类不要求实现通用意图分类器；可选状态/过滤能力也不自动进入首版。

## 1. 核心思路

记忆检索负责找出相关记录；回答模型负责结合问题解释这些记录。检索分数只表示“与问题相关”，不能单独证明哪条事实是真的、更新或更适用于当前。

```text
用户问题 + 可信用户/项目范围
  → 搜索相关记忆候选
  → 将记忆内容、来源和可用时间一起交给回答模型
  → 模型基于证据回答；证据不足时说明限制
```

首版不要求另建一个通用“当前/历史/事件/来源意图分类器”。搜索使用原始问题和可信范围，返回少量相关记忆及其证据元数据。日期、属性或来源限制先随问题交给回答模型理解；应用以后明确提供过滤参数时，再按后端已支持的能力执行，不要求首版自动解析这些限制。

## 2. 候选记忆应带哪些证据

以下是**回答上下文的最小候选格式**，不等于每个字段都必须成为数据库必填列：

| 提供给模型的信息 | 用途 | 限制 |
|---|---|---|
| `content` | 说明记忆记录的内容。 | 不因检索分数高就视为确定事实。 |
| `source_refs`、来源类型和角色 | 回查原始消息/文档/工具记录；辨别是谁说的或观察到的。 | 角色表明来源，不自动证明来源可靠或已获用户确认。 |
| `observed_at` | 表示来源消息被系统接收/观察到的时间，可帮助排列陈述先后。 | 不等于事实真实开始或结束的时间。 |
| `valid_from`、`valid_to` | 若原始证据明确事实生效区间，帮助回答指定时点的问题。 | 未知就留空；不能用入库时间补造。 |
| `status`、新旧关联（若已有） | 说明记录是否被替代，以及可能的前后关系。 | 是额外证据，不应单独代替来源和时间判断；首版可以没有。 |
| `recorded_at`（通常只用于追踪） | 说明系统何时保存记录。 | 不作为事实发生时间或事实新旧的依据；旧对话补录尤其如此。 |

检索返回的记录可按已知来源时间排列，但排序只是方便模型比较，不能自动裁定事实。候选数可配置；首轮用例评估前不把某个 Top-k 数字定为正确值。

候选集不等于完整历史：语义搜索可能漏掉相关旧记录。若一个问题要求完整时间线或完整审计，单次 Top-k 搜索不足；需要明确的结构化查询或补充历史读取。这是检索覆盖边界，不能让回答模型弥补它没看到的证据。

## 3. 回答约定

- 先遵守可信用户/项目范围；绝不让语义相关性越过范围隔离。
- 当前状态问题：比较候选的来源、角色、消息时间和已有状态标记。可以说“最近一次明确记录是……”，不能仅凭较新的入库时间断言事实从那时开始成立或一直持续到现在。
- 历史/“之前”问题：旧记录仍可作为候选。若时间或新旧关系支持，说明前后记录；否则说明只能确认先后报告，不能补出具体生效时间。
- 明确纠正：区分“先前说错”和“过去成立、后来变化”。旧条目可追溯先前陈述，不能因其较旧就把错误陈述包装成过去的真实事实。
- 指定日期问题：只有 `valid_from/to` 有证据时，才把结果表述为该时点的事实。只有消息时间时，表述为“截至该时点最后一次记录/报告”。
- 冲突问题：不能因为向量分高、记录入库较晚或某条排序靠前就自动选胜者；证据无法区分时并列说明或请求澄清。
- 没找到候选：说“本次记忆中没找到相关记录”，不推断“从未发生”。
- assistant 建议、工具观察、用户陈述和用户确认按来源区分，不互相冒充。

这些约定提供给回答模型的是“怎样使用证据”的简短指引，不意味着必须为每一种自然语言问法写一条规则。

## 4. 五类问题的桌面走查

| 问题类型 | 提供给模型的候选证据 | 期望回答 | 不应做的推断 |
|---|---|---|---|
| 问某项信息“现在是什么” | 同一范围内的相关记录、来源角色、可用消息时间、已有状态标记。 | 用证据最充分的最近一次明确报告作答；需要时说明报告时间。 | 不把最近写入的记录自动当成现实中的当前真相。 |
| 问“变化之前是什么” | 当前候选及相关旧记录；若已有新旧关联则一并提供。 | 返回可由来源/时间支持的前一条记录。 | 不把“之前”扩展成没有证据的完整历史区间。 |
| 问“某日/某段时间是什么” | 有效时间字段；若缺失，则提供来源消息时间并标明它只是报告时间。 | 依据有效区间回答，或明确只能给出截至该时点的最后一次报告。 | 不用 `recorded_at` 代替事实有效时间。 |
| 同主题候选互相矛盾 | 本次检索到的相关候选及其来源、角色、消息时间和已有关系。 | 证据足够时解释变化；不足时列出已检索到的冲突或请求澄清。 | 不声称候选集覆盖完整历史；不因相似度分数或写入先后强行选一条。 |
| 没有可用时间 | 内容与来源；时间字段为空。 | 回答不依赖具体日期的问题；对时间问题说明无法确定。 | 不以系统当前时间补造事实时间。 |

这只是基于设计规则的桌面检查，不是原型实验或准确率结论。若要判断时间/来源字段是否真的改善回答，后续需用同一批问题比较“只给内容”和“内容加证据元数据”两种上下文。

## 5. 三套实现给我们的边界

| 实现 | 检索如何接到回答链路 | 与证据包的关系 |
|---|---|---|
| Mem0 OSS | `search()` 返回记忆文档，应用再提供给 LLM；OSS 搜索可结合语义、关键词和实体信号。普通 OSS 召回不提供完整的事实时间推理。 | 可把存储文档及其已有元数据交给模型；需区分记录时间和事实时间。Mem0 Platform 的时间推理不能当作 OSS 默认行为。 |
| LangMem | `create_search_memory_tool` 返回 BaseStore 搜索到的内容/对象，Agent 通过工具结果回答；检索引擎取决于 Store 与索引配置。 | 可在自定义 schema 中加入时间/来源，再保证搜索工具结果包含它们；默认 schema 不自动带完整证据链。 |
| Graphiti | 普通搜索返回相关事实关系；高级搜索可配置搜索方法、过滤器和重排。 | 关系数据可包含 `valid_at`/`invalid_at` 和 episode 来源；时间过滤可由调用方明确设置。普通搜索结果仍需交给 Agent 解释，不能假定默认只返回当前事实。 |

## 6. 本草案暂时不决定的事

- 不规定必须有 `kind`、`topic`、`status` 或 `supersedes_id`；它们是否必要，要看候选证据是否能被稳定写入，以及桌面/原型评估中是否确实缺少这些信息。
- 不规定普通查询必须过滤所有旧记录；旧记录可能是回答“之前”的关键证据。由可信范围过滤是硬约束，状态和时间用于理解候选，不是无条件删掉历史。
- 不承诺仅凭模型就能从缺失的时间信息中恢复事实有效时间。
- 不把这份草案视为完成的检索实现或准确率评估。
