# Agent 长期记忆：调研与实现推进计划

> 交接阅读入口：[v1 设计与实施说明](agent_long_term_memory_v1_design.md)的实施说明 16、17；17 记录 2026-10-09 第二批增量和第一轮真实组合观察，15 是前一轮审核记录。当前实现约定以 v1 文件为准，本文记录累计进度。

## 目标

设计并实现适合本项目需求的 agent 长期记忆系统。主要工作是理解记忆系统本身如何抽取、组织、更新、维护和召回记忆；DB-GPT 现有能力盘点及后续接入属于支撑工作，不作为记忆设计的出发点。

Mem0、LangMem 和 Graphiti 是重点研究对象。研究目标不是简单拼接功能，也不预设其中任何一个必须成为基座，而是根据源码实现、目标需求和工程约束，决定复用、改造或自行实现哪些部分。

## 范围与边界

### 主要范围

- 对话、事件和 agent 活动中哪些内容值得成为长期记忆。
- 如何从消息中抽取记忆，并保留事实、偏好、事件、关系及上下文。
- 如何检索可能重复、相关或冲突的旧记忆。
- 如何决定新增、合并、更新、失效、删除或不操作。
- 如何表达事实来源、置信度、观察时间、事件时间和有效时间。
- 如何按查询召回记忆，并将结果组织成 agent 可用的上下文。
- 如何限制错误抽取、错误合并、过度记忆、遗忘和跨用户数据混淆。
- 是否以 Mem0、LangMem 或 Graphiti 为代码基座，以及依赖、许可和改造成本。

### 次要范围

- DB-GPT 中现有 agent 和记忆组件的接入点。
- 新记忆系统在 DB-GPT 的配置、存储和调用方式。
- 现有数据迁移及兼容方案。

这些接入问题在记忆模型和主流程确定后再详细处理。

## 工作原则

1. **以真实实现为准。** 文档用于定位设计，结论要回到具体版本、源码路径、提示词、数据结构和执行流程核对。
2. **严格区分版本和组件层次。** 尤其区分 Mem0 不同版本的写入策略；区分 LangMem 的无状态管理器、Store Manager 和应用自定义逻辑；区分 Graphiti 的图记忆核心与其外围托管服务。
3. **标注能力归属。** 对每项功能说明它是框架默认行为、可配置能力、底层存储能力，还是调用方必须自行实现。
4. **保留证据与不确定性。** 记录源码位置、调用链和待验证项，不把模型推断或产品文案写成系统保证。
5. **基座选择后置。** 开源代码降低复用门槛，但不预先假设集成工作量小；在检查架构、依赖、许可和数据模型后再估算。
6. **记忆历史可审计。** 设计阶段重点评估如何保留来源和变更历史，使错误更新能够追溯或恢复。
7. **优先复用开源实现。** 能直接复用就直接复用，需调整时按固定源码和示例小范围适配；新增设计只用于已确认需求的缺口，不预设复杂字段、状态机或检索融合。

## 分阶段计划

### 阶段 1：定义目标场景与记忆要求

列出首期需要支持的典型输入、记忆和查询场景，例如：

- 用户陈述稳定偏好或个人事实。
- 用户计划、目标或状态随时间改变。
- 对话中出现重复信息、补充信息或相互矛盾的信息。
- agent 产生的建议、执行结果和用户确认需要分别归属。
- 查询当前状态、历史状态、变化时间和事实来源。

对每个场景记录期望写入结果、旧记忆处理方式、查询结果，以及不能接受的错误。此阶段确定问题边界，不提前锁定存储方案或基座。

**交付物：** 场景清单、术语定义、首期需求和质量标准。

### 阶段 2：源码级审查三个候选项目

对 Mem0、LangMem 和 Graphiti 使用相同审查模板，分别追踪真实调用链：

1. **输入：** 接收哪些消息、角色、时间和元数据；上下文窗口如何形成。
2. **抽取：** 抽取什么粒度的记忆；模型提示、结构化 schema 和来源归属如何工作。
3. **写入时检索：** 是否找旧记忆；查询由什么内容构造；使用什么检索方式、范围和数量；结果如何提供给模型。
4. **更新与冲突：** 决策动作有哪些；判断依据是什么；时间、来源和置信度是否参与；旧记录是覆盖、失效、删除还是保留。
5. **存储模型：** 记忆条目、关系、episode、元数据、历史和索引包含哪些字段。
6. **普通召回：** 写入时的候选检索与用户查询时的记忆召回分别如何实现；有无混合检索、过滤、重排和图遍历。
7. **生命周期：** 去重、合并、遗忘、过期、反馈和纠错如何实现。
8. **运行特性：** 调用次数、异步路径、失败处理、并发、可观测性和可扩展点。
9. **工程约束：** 依赖、可用存储、模型适配、许可证及需要托管服务的能力。

Mem0 必须分别记录历史版本和当前选定版本的实际行为。LangMem 必须区分管理器、Store Manager 和 agent tools。Graphiti 必须区分图关系的时间有效性、episode 时间及系统记录时间。

**交付物：** 三份源码审查记录、统一对比表、版本与证据索引、未确认事项清单。

### 阶段 3：形成设计取舍和系统方案

将审查结果映射到阶段 1 的场景，逐项回答：

- 哪些问题由框架自动解决，哪些还需要调用方策略。
- 哪些做法可直接采用，哪些需要更改才能满足目标。
- 对冲突事实，系统要保留什么历史、如何确定当前状态、何时允许自动更新。
- 如何区分“何时获知”与“事实何时成立”，缺少时间信息时如何表示不确定性。
- 哪些内容适合结构化记忆，哪些应保留为原始 episode 或证据。
- 如何将精确字段检索、语义检索、关键词检索和关系检索组合起来。

设计候选写入流程，例如“接收来源记录 → 抽取候选记忆 → 检索相关旧记忆 → 评估重复、演变或冲突 → 写入新版本或关系 → 保留审计记录”。此流程是待论证的设计草案，不预先规定一定采用哪种冲突算法。

**交付物：** 目标架构、数据模型草案、写入和召回流程、冲突策略选项、主要失败模式及权衡说明。

### 阶段 4：选择基座并评估改造量

根据设计目标评估以下路线：

- 直接基于某个候选项目改造。
- 复用其存储或管理组件，在本项目实现核心策略。
- 保留 DB-GPT 既有抽象，独立实现新的记忆核心。

评价维度包括：目标场景覆盖度、冲突和时间建模能力、存储及检索契合度、依赖和运行成本、许可证、代码可维护性、数据迁移风险，以及与目标架构的差距。

**交付物：** 有证据支持的基座推荐、备选方案、复用清单、改造任务拆分和成本范围。此阶段结束前不宣称改造量“大”或“小”。

### 阶段 5：实现独立记忆核心的最小纵向流程

先实现可独立描述和评估的核心能力，再连接 DB-GPT：

1. 接收一段对话并保留消息角色、来源和时间元数据。
2. 产出有来源依据的候选记忆。
3. 找到相关旧记忆并执行选定的去重、更新或冲突策略。
4. 保存记忆及其变更历史。
5. 按语义和结构化条件召回，并返回来源和时间信息。

实现时优先保证流程可观察、策略可配置、历史可追溯。暂不为未经确认的高级能力扩大范围。

**交付物：** 独立的记忆核心原型、配置边界、数据模型实现和已知限制。

### 阶段 6：按场景评估并迭代

使用阶段 1 定义的场景检查抽取完整性、重复控制、冲突处理、时间解释、来源追溯、召回相关性、用户隔离及延迟和成本。重点分析错误案例，更新策略和需求，而不只看单一总分。

**交付物：** 场景评估结果、失败案例、策略调整和是否进入集成的判断。

### 阶段 7：接入 DB-GPT

在记忆核心和数据契约稳定后，再接入 DB-GPT 的 agent 生命周期、配置和存储设施。评估现有 agent 观察/执行记录与新语义记忆之间的边界，避免把操作轨迹直接当成用户事实。最后制定旧数据兼容、迁移和回滚方案。

**交付物：** DB-GPT 适配层、配置与调用说明、迁移方案及集成限制。

## 阶段门槛

- **进入源码审查：** 首期场景和术语已明确。
- **确定目标架构：** 三个候选的关键调用链和边界已由源码核实。
- **确定基座：** 目标设计、依赖、许可证、存储契合度和改造差距均已比较。
- **进入 DB-GPT 集成：** 独立记忆核心已覆盖首期关键场景，并且数据契约稳定。

## DB-GPT 现状的初步备注

当前仓库中已有 `Memory`、`MemoryFragment`、`LongTermMemory` 和 `HybridMemory` 等组件；长期记忆使用向量存储，并包含重要性和访问时间等召回因素。agent 层也有现成的读写入口。现有实现主要围绕 agent 观察或活动记录组织，整理、遗忘和清理等生命周期能力仍有待完善。

这只是接入阶段的背景信息，**不作为长期记忆设计的基准，也不改变本计划以记忆机制本身为主线的安排**。
